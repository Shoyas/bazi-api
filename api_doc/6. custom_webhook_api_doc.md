# Custom Outbound Webhooks API Documentation

Welcome to the **Custom Webhook Subsystem** API documentation. This enterprise feature enables **PRO** and **PREMIUM** subscribers to register custom HTTPS webhook endpoints, subscribe to real-time astrology and quota events, and receive HMAC-signed JSON payloads with automatic retries via BullMQ.

---

## Overview & Capabilities

| Property | Description |
| :--- | :--- |
| **Base URL Path** | `/api/v1/custom-webhooks` |
| **Authentication** | Bearer JWT Token (`Authorization: Bearer <token>`) |
| **Plan Availability** | **PRO** (up to 3 endpoints) & **PREMIUM** (up to 10 endpoints) |
| **Security Mechanism** | HMAC-SHA256 Signature Header (`x-bazi-signature`) |
| **Retry Strategy** | 3 attempts with exponential backoff (5s, 10s, 20s) |

---

## Supported Webhook Events

| Event Name | Trigger Time | Description |
| :--- | :--- | :--- |
| `solar_term.changed` | When a Solar Term begins | Broadcasts when a new solar term boundary (Jie Qi, e.g., Lichun, Chunfen, Dongzhi) starts. |
| `daily.bazi_shift` | Daily at 00:00 (Midnight) | Broadcasts the new day's Heavenly Stem, Earthly Branch, Day Pillar, Wu Xing, and Zodiac. |
| `usage.threshold_reached` | Real-time on API call | Alerts when your account hits 80% or 100% of your rate limit / API quota. |
| `test.ping` | On-demand via API/Dashboard | Instant test payload to verify endpoint connectivity and HMAC signature validation. |

## Endpoints Reference

### 1. Register Webhook Endpoint (`POST /api/v1/custom-webhooks`)

Register a new outbound webhook destination. A unique HMAC verification secret (`secret`) is generated automatically.

**Headers:**
```http
Authorization: Bearer <your_jwt_token>
Content-Type: application/json
```

**Request Body (JSON):**
```json
{
  "url": "https://your-domain.com/api/webhooks/bazi",
  "description": "Production Webhook Receiver for Astrology App",
  "events": [
    "solar_term.changed",
    "daily.bazi_shift",
    "usage.threshold_reached",
    "test.ping"
  ]
}
```

**Success Response (`201 Created`):**
```json
{
  "success": true,
  "statusCode": 201,
  "message": "Custom webhook endpoint registered successfully.",
  "data": {
    "id": "c7f99b2e-0a56-43b9-a9a7-9f1e8e82d1c0",
    "userId": "user-uuid-here",
    "url": "https://your-domain.com/api/webhooks/bazi",
    "description": "Production Webhook Receiver for Astrology App",
    "secret": "whsec_3f8b91a27e4d8c6b5a0f1234567890abcdef",
    "events": [
      "solar_term.changed",
      "daily.bazi_shift",
      "usage.threshold_reached",
      "test.ping"
    ],
    "isActive": true,
    "createdAt": "2026-08-16T12:00:00.000Z",
    "updatedAt": "2026-08-16T12:00:00.000Z"
  }
}
```

> **Security Note:** Store the `secret` securely on your receiving server to verify incoming signatures.

## Incoming Webhook Request Format & Headers

When an event triggers, BaZi API dispatches an HTTP `POST` request to your registered URL with the following HTTP headers:

```http
POST /api/webhooks/bazi HTTP/1.1
Host: your-domain.com
Content-Type: application/json
User-Agent: BaZi-Webhook-Dispatcher/1.0
x-bazi-event: daily.bazi_shift
x-bazi-timestamp: 2026-08-16T00:00:00.123Z
x-bazi-signature: a3f87b2190e21bc89a74f... (HMAC-SHA256 hex string)
```

## Verifying Webhook Signatures

To ensure incoming requests genuinely originated from BaZi API and were not tampered with, compute the HMAC-SHA256 signature of the raw request body using your webhook `secret` and compare it with the `x-bazi-signature` header.

### Verification in Node.js / Express

```javascript
const crypto = require('crypto');
const express = require('express');
const app = express();

// Use express.raw or express.json({ verify: ... }) to get raw body
app.use(express.json());

app.post('/api/webhooks/bazi', (req, res) => {
  const signature = req.headers['x-bazi-signature'];
  const event = req.headers['x-bazi-event'];
  const secret = process.env.BAZI_WEBHOOK_SECRET; // e.g. whsec_...

  const rawBody = JSON.stringify(req.body);
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('hex');

  // Constant time comparison
  if (signature !== expectedSignature) {
    console.warn('⚠️ Invalid webhook signature rejected.');
    return res.status(401).send('Invalid signature');
  }

  console.log(`✅ Verified Webhook Event: ${event}`, req.body.data);

  // Return 200 OK promptly
  res.status(200).json({ received: true });
});

app.listen(3000, () => console.log('Webhook listener running on port 3000'));
```

### Verification in Python (Flask / FastAPI)

```python
import hmac
import hashlib
import json
from flask import Flask, request, jsonify

app = Flask(__name__)
WEBHOOK_SECRET = "whsec_your_secret_here"

@app.route('/api/webhooks/bazi', methods=['POST'])
def handle_bazi_webhook():
    signature = request.headers.get('x-bazi-signature')
    event = request.headers.get('x-bazi-event')

    # Compute expected HMAC
    raw_body = request.get_data()
    expected_signature = hmac.new(
        WEBHOOK_SECRET.encode('utf-8'),
        raw_body,
        hashlib.sha256
    ).hexdigest()

    if not hmac.compare_digest(signature, expected_signature):
        return jsonify({"error": "Invalid signature"}), 401

    payload = request.json
    print(f"Received verified event: {event}", payload)

    return jsonify({"received": True}), 200

if __name__ == '__main__':
    app.run(port=3000)
```

## Best Practices

1. **Acknowledge Quickly:** Return an HTTP `200` or `204` status within 5 seconds. If you have long-running tasks, process them in a background queue after acknowledging.
2. **Handle Retries Idempotently:** Use the `timestamp` and event `data` to avoid executing duplicate actions if a network blip causes a retry.
3. **Use HTTPS:** Webhook receiver URLs should use HTTPS with a valid SSL certificate.
